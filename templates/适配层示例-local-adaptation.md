# 本地适配层 · 环境事实（示例）

> 本文件记**环境的事实**：库在哪、归类总表在哪、各项目的分类表与登记点、移动笔记的本机做法。
> **本文件在同一环境的所有 agent 下应当逐字节一致**——环境值只有这一处真源，改完复制到各处。
> "本 agent 能用什么工具、有什么能力限制"不放这里，见同目录 `harness.md`。
> **真源与分发**：真源 = `<你指定的一份>`；改动一律从真源发起再分发到各处。

- 笔记库路径：`D:\vault\my-notes`（POSIX 形态 `/d/vault/my-notes`，只在 Git Bash / WSL 下有效）
- **归类总表**：`知识库约定.md`（库根）
- **项目内分类表**：

| 一级项目 | 项目内分类表 |
|---|---|
| `k8s` | `k8s/k8s 项目分类表.md` |
| `平台管理` | `平台管理/平台管理 项目分类表.md` |

- **自动索引**：`<项目>/INDEX.md` 由工具生成，是 **L0 入口、只读、不要手改**；落后时用工具重建。
  **命名区分（易错）**：`INDEX.md` 是工具产物，`<项目名> 项目分类表.md` 才是人维护的登记点。

## 3. frontmatter 最小归类字段（新笔记）

- `tags` 第 1 位 = **项目标签，与一级目录名逐字一致**（`k8s` / `平台管理`），第 2 位 = 体裁或一级分类；其后自由
- `summary` 必填（自动索引页与检索摘要取它；缺了会回退显示**正文首行**，所以正文首行要写一句人话，别以 `##` 节名开头）
- 体裁 skill 规定的其它字段照其规定
- **只约束新笔记**；存量回填范围要写清楚（"哪些回填了、哪些不回填"），避免静默改存量

## 4. 目录配套动作

> 通用层说的「**目录配套动作**」在本库具体指什么。**不用 Obsidian 或没装图标类插件时，本节整节删掉，通用层不会因此失效。**

- 例：装了 Iconize —— 新建目录后右键 → Change icon…；图标配置由插件自己写 `data.json`，**不要手改**。
- 例：不用图标 —— 新建目录后的配套动作 = 只在项目分类表 §1 登记一行。**不预建空目录**。

## 5. 搜索与移动的本机做法

- 先自测检索手段在不在（判据用 `grep`，不要用 `bash`），**没有 GNU grep 就换本机 shell 的等价写法**（PowerShell 用 `Get-ChildItem` + `Select-String`）。
- 库**没有版本管理**时，批量移动前先整库备份到库外，**打完包立刻试解压校验**，并在包名旁注明用什么工具打的（不同 `tar` 实现对非 ASCII 路径不互通）。
- 在库外用文件工具移动：**库不会自动改链接**——移动前查出全路径链接，移动后逐条改；短链接（按文件名解析）不受影响，前提是**文件名全库唯一**。
- 移动记录写进操作记录，含"原路径 → 新路径"清单，便于回滚。
