# 本地适配层 · 环境事实（technical-writing）

> 本文件记**环境的事实**。本 skill 是跨体裁的通用写作纪律，**不含环境值**；本文件只说明在换环境时它需要跟着变什么。
> **本文件在同一环境的所有 agent 下应当逐字节一致。**

## 1. 本 skill 与环境的关系

`technical-writing` 的四节（真实性规则、硬性规则、文风、内容完整性）**不含路径、库名、集群名、工具名**，换环境、换项目、换文档库都不需要改。

因此本 skill **通常不需要本文件**——留空且不填是正常状态，`SKILL.md` 自带完整语义。

## 2. 确实需要本地化时的唯一情形

只有在"**本环境的文风标准与 §3 正本冲突**"时才需要记录差异，例如：

- 组织有强制的术语表或禁用词表（与 §3 替换表不一致）；
- 输出语言不是中文（§3 是标准技术中文的口径）；
- 有书面的写作规范需要引用（把出处与要点写在这里）。

记录格式：

| 冲突项 | 本环境要求 | 与 `SKILL.md` §3 的关系 |
|---|---|---|
| `<术语/写法>` | `<本组织要求>` | 覆盖 / 补充 |

## 3. 真源与分发

- 真源：本方案内的一份 `technical-writing/`；改动从真源发起再分发到各 agent 目录。
- 本文件与 `harness.md` 在各运行环境下应保持一致；`SKILL.md` 是通用层，不存在环境副本。
