# dsh-obsidian-note-kit

一套可开箱部署的笔记工作流：让 AI agent 按规矩往 Obsidian 笔记库里写东西——**放哪**（归类）、**怎么写**（知识笔记 / 故障复盘），并且做到**规则只放一处、环境事实只放一处**。

含四份 skill、库内规则表模板、必需依赖插件 `dsh-kb` 的内置副本，以及从零开始的部署步骤。

---

## 它解决什么问题

没有规矩时，agent 往笔记库写东西的典型症状：

| 症状 | 后果 |
|---|---|
| 落点随意 | 同一主题散在三个目录；冒出"故障排查"和"故障手册"这类同义目录 |
| 规则漂移 | 写作规范散落在多个 skill、多份副本里，改一处漏两处 |
| 环境耦合 | skill 里写死路径与集群名，换台机器或换个人就废 |
| 编造内容 | 缺信息时用"合理推测"填空——而一份编得像样的复盘会被当成事实引用 |

这套东西的应对，浓缩成一句口诀：

> **内容定项目，体裁定命名，范围定层级；能沿用就不新建，拿不准先问。**

以及两条硬规则：**规则本体只有一处**（笔记库内的归类总表），**环境事实只有一处**（各 skill 的适配层）。

## 包含什么

| 路径 | 内容 |
|---|---|
| `skills/technical-writing/` | **通用写作纪律**（跨体裁）：真实性规则 / 硬性规则 / 换词表 + 换句式表 / 内容完整性 / 规则怎么长。另三个 skill 的写作规则以它为准 |
| `skills/obsidian-note-placement/` | **放哪**：三步判定 / 八条规则 / 查重定位 / 登记 / 存量巡检 / 自更新约定 |
| `skills/k8s-obsidian-notes/` | 知识笔记**怎么写**：8 节骨架 / 字段口径 / 写作姿态 / 语言标准表 |
| `skills/writing-postmortems/` | 故障文档**怎么写**：完整复盘骨架 + 报错信号卡骨架 / 规则 / 维护约定 |
| `templates/归类总表模板.md` | 笔记库根的规则表模板——各 skill 的判定依据 |
| `templates/适配层示例-*.md` | 适配层**填好之后**长什么样的脱敏示例（`local-adaptation` / `harness` 各一份） |
| `vendor/dsh-plugins/dsh-kb/` | 必需依赖 `dsh-kb` 的内置副本（MIT，保留原 LICENSE） |

`skills/*/references/` 下的两个文件**本身就是模板**（含占位符与逐项填写指引）；`templates/适配层示例-*.md` 是它们**填好之后**的样子，用来对照颗粒度——**只读不拷**，别把示例当模板复制进 `references/`。

## 三层结构（为什么这样分）

| 层 | 文件 | 换环境时怎么办 |
|---|---|---|
| **通用层** | `skills/*/SKILL.md` | **原样不动**——不含库路径、项目名、工具名、分类名 |
| **环境事实** | `skills/*/references/local-adaptation.md` | **重写**：库在哪、落点惯例、字段取值、登记点、素材源 |
| **能力层** | `skills/*/references/harness.md` | **重写**：目标宿主 agent 的写入通道与限制 |
| **规则本体** | 笔记库根的「归类总表」 | **先在目标库建立**，skill 不复制它 |

这样分的收益：规则随库一起演进、只有一份；skill 本体可以原样搬去任何库；换宿主机只动一个文件。

## 部署：从 0 到 1

### 第 0 步 · 确认前提

| 前提 | 说明 | 必需 |
|---|---|---|
| 一个能加载 skill 的宿主 agent | DSH / Qoder / Claude Code / Codex 任一 | 是 |
| 一个 markdown 笔记库 | Obsidian vault 或任意 md 目录树 | 是 |
| 一种检索 / 查重手段 | `dsh-kb`（本仓库内置）或 rg / grep / 库自带检索 | 是 |

**不用 Obsidian 也可以**：方案只要求"md 笔记库 + 能查重检索"。此时跳过所有图标相关配置，适配层里对应小节整节删掉即可——通用层不会因此失效。

### 第 1 步 · 部署 dsh-kb（以 DSH 为宿主时）

`dsh-kb` 提供 `kb_*` 工具族：L0 索引、分层检索、收件箱、库体检、索引重建。它是**唯一**提供"自动索引 + 检索"的依赖，本方案的查重与登记环节会用到。

1. 把 `vendor/dsh-plugins/dsh-kb/` 拷到你放插件源码的位置，例如 `<你的插件目录>/dsh-kb/`
2. 在 DSH profile 的 `package.json` 里把它加成依赖，并列入 bundle 列表：

   ```json
   {
     "dependencies": {
       "dsh-kb": "link:<你放 dsh-kb 的绝对路径>"
     },
     "dsh": {
       "profile": {
         "bundles": [ "...", "dsh-kb" ]
       }
     }
   }
   ```

   参考形态是 `"dsh-kb": "link:<你的插件目录>\\dsh-kb"`，profile 位于 `~/.dsh/profiles/<profile名>/`。

3. 让插件依赖就位（`dsh-kb` 的运行期依赖极少，若报缺包，在其目录里装一次即可）
4. **重启 DSH**
5. 验证：工具表里应出现 `kb_index` / `kb_search` / `kb_read` / `kb_doctor` / `kb_reindex` 等

> `lib/client.js` 是已构建好的 web 面板产物（含"知识中心 → 洞察 → 重建索引"按钮），**不需要重新构建**。只有改了 `lib/client-source.js` 才需要跑 `npm run build:client`。

**非 DSH 宿主**：跳过本步。用 rg / grep / 库自带检索替代查重环节，并在 `harness.md` 里把你的写入通道写清楚。

### 第 2 步 · 建笔记库

```bash
mkdir -p my-vault
```

结构自定，但**根目录要能放一份总表**（下一步）。建议一级目录即"项目"。

### 第 3 步 · 放 skill 到位

把 `skills/` 下三个目录整体拷进宿主 agent 的 skill 目录。常见位置：

| 层级 | 路径 |
|---|---|
| 用户级 | `~/.dsh/skills/`、`~/.codex/skills/`、`~/.qoder/skills/` |
| 项目级 | `<项目>/.dsh/skills/`、`<项目>/.claude/skills/`、`<项目>/.qoder/skills/`、`<项目>/.codex/skills/` |

**三个必须一起装**——`writing-postmortems` 的语言标准指向 `k8s-obsidian-notes` 通用层 §4.2（已内联最小原则可降级，但完整替换表在那边）。

> **多副本提醒**：如果同一台机器上有多个宿主，skill 会在多处存在，且各宿主解析顺序不同（项目级通常优先）。**指定一份为真源，改动一律从真源分发到各处**，否则会出现版本漂移。

### 第 4 步 · 建「归类总表」

复制 `templates/归类总表模板.md` 到笔记库**根目录**（文件名自定，如 `知识库约定.md`），填上：

1. **项目边界**——每个一级目录收什么、不收什么
2. **体裁表**——有哪几种文档、各自的文件名格式与写作规范
3. frontmatter 最小字段约定

**这一步不能跳**：归类 skill 的每一条判定依据都指向这张表。

### 第 5 步 · 填 `local-adaptation.md`

这三个文件本身就是模板（`technical-writing` 的适配层通常为空，不含环境值，可跳过）。逐项把占位符换成你的库事实：

| 小节 | 填什么 |
|---|---|
| 库与落点 | 库路径、本体的落点惯例、命名规则、参考实例 |
| frontmatter 取值 | 你库实际用的键与取值来源 |
| 索引与登记 | 哪些是自动索引（只读）、哪些要手写、登记行格式 |
| 目录配套动作 | **可选**——如果用 Obsidian + Iconize 就是配图标；不用就整节删掉 |
| 素材源 | **可选**——只读知识库路径；没有就不填 |
| 环境专属信息 | 脱敏清单、哪些内部标识要保留原文 |

**这几份内容各不相同**（各自管本体的落点与登记），别复制粘贴同一份。

### 第 6 步 · 填 `harness.md`

同样按模板填：你所在的运行环境、可用的写入手段、索引刷新方式、能否代跑远端命令。

**这四份内容相同**（四个 skill 共用），改一份要同步其余三份。

### 第 7 步 · 装可选依赖

| 依赖 | 什么时候需要 |
|---|---|
| Obsidian + Iconize | 想让目录有图标（否则跳过整个图标配置） |
| Obsidian 的 MCP 写入通道插件 | 想让 agent 通过插件 API 改 frontmatter 而不是直写文件 |
| Git Bash / POSIX shell | 想直接跑通用层给的 bash 参考命令（否则用本机 shell 的等价写法） |
| Python + PyYAML | 想校验 frontmatter 的 YAML 合法性 |

详见 [DEPENDENCIES.md](DEPENDENCIES.md)。

## 验证部署

别只看配置文件，**写一篇真笔记跑一遍**：

1. 让 agent 处理一篇内容（如"读一段代码，沉淀其中的机制"）
2. 它应当输出一行归类决定：`归类：<项目> / <体裁> / <路径> ｜ 依据：<R几> ｜ 登记：<索引>`
3. 检查落盘结果：文件在正确的目录、frontmatter 齐全（`summary` 非空）、wikilink 目标真实存在
4. 检查登记：该登的手维护索引登了、登的是新路径
5. 检查没有多余动作：没有把内容塞进不贴切的目录、没有预建空目录

跑不通时按这个顺序查：**总表建了吗 → 适配层填了吗（尤其库路径）→ skill 装在宿主真正加载的位置了吗**。

## 日常怎么用

| 说什么 | 触发什么 |
|---|---|
| "把这写成知识笔记" | 归类 + 知识笔记骨架 |
| "写个故障复盘" / "把这次故障成文" | 归类 + 完整复盘骨架 |
| "补一张报错信号卡" | 归类 + 信号卡骨架 |
| "这篇放哪" / "帮我归类" / "整理一下 Inbox" | 只走归类判定 |
| "检查有没有放错位置的笔记" / "这个目录结构合理吗" | 存量巡检（只报告，不擅自移动） |

## 依赖

## 跨环境迁移

把方案搬到第二台机器时，**先把手上的资产分三类，别一锅端**——三类的处理方式完全不同：

| 类 | 典型 | 怎么处理 |
|---|---|---|
| **① 能公开取的** | 主题、图标包这类有官方发布渠道的资产 | 从发布源重新取，版本与源环境对齐 |
| **② 能从本机标的** | 键名、匹配语义、变量归属、配置到底落在哪个文件里 | 在本机的插件/本体源码里查证后再写。**"语义近似"不等于"等价"**：照字面把旧键名"翻译"成新键名最容易踩空（旧键可能在新版里已不存在，或语义不同） |
| **③ 只有源环境知道的** | 自写片段内容、个性化取值（颜色/参数）、按旧库目录写下的键 | **不要猜**：列成清单让对方出补丁包，或直接拷文件 |

三条配套纪律：

- **先退出宿主再改配置**：宿主运行中改它的 `data.json`，会被插件在下一次保存时回写覆盖。
- **配置在 `data.json` 里，不在插件本体里**：只拷插件目录、不拷配置，结果是"装了但什么都没配"。
- **模板改了要重新分发**：适配层是"真源 → 各宿主副本"的关系（见各文件开头的「真源与分发」），只改一处就会漂移。

> 拿不准某个值属于哪一类时，判据是：**换一台机器它还成立吗？** 成立 → 通用层（`SKILL.md`）；只在本机成立 → 适配层（`references/`）；只有对面那台机器知道 → 要文件，别写。

## 已知限制

- **适配层完全缺失也能工作**：通用层自带降级描述——用空库沙盒实测过，纯靠通用层 + 库内自己的总表，六步流程全部走通。
- **未覆盖**：故障复盘与报错信号卡的迁移路径没单独跑过演习；它们的落盘 / 登记逻辑与知识笔记同构。
- **走 MCP 的写入通道在"任一侧重载"后会失效**：这类通道是 sessionful 的（客户端持 session id，服务端按 session 记状态），服务端插件重载或宿主重启会清掉 session、而客户端还握着旧 id，下一次调用报 `Session not found`——换参数重试无用。处理与预防见 `references/harness.md` §2「共同限制」。
- **配置类改动都是"写盘 → 重载 → 回读"三步**：只写盘不重载等于没改；反过来先重载再写盘会被宿主的下一次保存盖掉。同上，细节见 `references/harness.md` §2。
- `k8s-obsidian-notes` 的名字带 k8s，但它同样管平台功能类笔记。改名会牵动多处交叉引用，故保留原名，靠 `description` 说明覆盖面。
- 信号卡的 `## 现场` 节只在两种情况写（同一报错跨环境形态不同 / 需标明首次观察环境），其余情况删掉——避免它退化成"每张卡都有"的冗余节。
