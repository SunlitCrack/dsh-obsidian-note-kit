# dsh-obsidian-note-skills

让 AI agent 按规矩往笔记库里写东西——**放哪**（归类）、**怎么写**（知识笔记 / 故障复盘）、**环境事实与规则分开**。

三份 skill + 一份库内规则表，可整体迁移到其它 Obsidian 库或其它宿主 agent。

## 包含什么

| skill | 管什么 |
|---|---|
| `obsidian-note-placement` | **放哪**：判项目、判体裁、判目录层级、查重、登记，并在出现新边界时回写归类规则 |
| `k8s-obsidian-notes` | 知识笔记**怎么写**：骨架、字段口径、写作姿态、语言标准 |
| `writing-postmortems` | 故障文档**怎么写**：完整复盘骨架、报错信号卡骨架、规则 |

三者不是三件独立的事：归类 skill 决定落点，写作 skill 决定形态，而**规则本体（归类总表）放在笔记库里**，由所有 agent 共读。

## 设计：三层分离

| 层 | 文件 | 换环境时 |
|---|---|---|
| **通用层** | `skills/*/SKILL.md` | **原样不动**——不含库路径、项目名、工具名、分类名 |
| **环境事实** | `skills/*/references/local-adaptation.md` | **重写** |
| **能力层** | `skills/*/references/harness.md` | **重写**（按目标宿主） |
| **规则本体** | 笔记库根的「归类总表」 | **先在目标库建立**，skill 不复制 |

为什么这样分：规则只有一处（库内总表，随库一起演进），环境事实只有一处（适配层），skill 本体只描述流程——不会出现"改一处、漏两处"的规则漂移。

## 快速开始

1. 把 `skills/` 下三个目录拷进宿主 agent 的 skill 目录（如 `~/.dsh/skills/`、项目级 `.dsh/skills/`）
2. 在笔记库根建「归类总表」——见 [`templates/归类总表模板.md`](templates/归类总表模板.md)
3. 填三份 `skills/*/references/local-adaptation.md`——**文件本身就是模板**，内含填写指引，把占位符换成你的库事实
4. 填三份 `skills/*/references/harness.md`——同上；**三份内容相同，改一份要同步另两份**
5. 装依赖：见 [DEPENDENCIES.md](DEPENDENCIES.md)
6. 跑一遍验证：写一篇真笔记，走完 **定落点 → 查重 → 写 → 登记 → 互链 → 自检**

## 核心口诀

> **内容定项目，体裁定命名，范围定层级；能沿用就不新建，拿不准先问。**

## 已知限制

- **三个 skill 必须整体迁移**：`writing-postmortems` 的语言标准指向 `k8s-obsidian-notes` 通用层 §4.2。已内联最小原则（未装则按原则自行推导），所以拆开也能跑，但完整替换表、豁免词与例外清单只在 `k8s-obsidian-notes` 里。
- **适配层完全缺失也能工作**：通用层自带降级描述——用空库沙盒实测过，纯靠通用层 + 库内自己的规则表，六步流程全部走通。
- **未覆盖**：故障复盘与报错信号卡的迁移路径没有单独跑过演习；它们的落盘 / 登记逻辑与知识笔记同构，风险较低。
- `k8s-obsidian-notes` 的名字带 k8s，但它同样管平台功能类笔记。改名会牵动多处交叉引用，故保留原名，靠 `description` 说明覆盖面。

## 依赖
